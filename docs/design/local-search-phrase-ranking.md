# 本地搜索多词 AND 与短语优先设计

## 背景

当前站点使用 VitePress 本地搜索，保留了默认的模糊匹配与前缀匹配。
这能提升召回率，但多词查询仍按普通词项检索处理，导致：

- `git add` 这类查询无法稳定把真正包含连续短语的文档排在最前；
- 多词命令式查询更接近“任意词命中”，而不是“所有词都命中，再优先连续短语”。

## 目标

在不牺牲现有 fuzzy/prefix 体验的前提下，补齐多词查询语义：

- 单词查询继续保持原有行为；
- 多词查询改为 `AND`，要求所有词项都命中；
- 若文档中存在连续短语，例如 `git add`，则给予额外加权，使其排序前移。

## 方案

分两层实现。

### 1. 索引层

对英文/命令类 token，在原有单词 token 之外，额外生成相邻双词短语 token。

示例：

- 原始文本：`git add .`
- 基础 token：`git`, `add`
- 额外短语 token：`git add`

这样不会破坏原有模糊搜索，但为“连续短语加权”提供可命中的索引项。

### 2. 查询层

当查询被解析为多个 token 时，构造组合查询：

- 主查询：所有词项按 `AND` 命中；
- 短语查询：相邻双词短语按精确 token 命中，并给予更高权重；
- 最终结果：两部分结果做并集，连续短语命中的文档因额外得分而排前。

## 不变量

1. 单词查询路径不变，仍保留 fuzzy/prefix 召回。
2. 多词查询至少要求基础词项全部命中。
3. 短语加权只影响排序，不放宽基础词项约束。
4. 仅为相邻英文 token 建立短语 token，避免索引尺寸无界增长。
